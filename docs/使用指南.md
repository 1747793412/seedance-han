# Seedance Han 使用指南

## 1. 准备输入

先提供你已知的信息，不必为填表而编造缺失项：

- **用途与观众**：给谁看，放在哪里，希望观众看懂什么。
- **内容与风格**：产品或人物是谁，在哪里，发生什么，喜欢什么视觉感觉。
- **交付约束**：时长、画幅、有无口播、是否需要配乐；未确定可请技能推荐。
- **参考素材**：产品图、人物图、场景图或上一段成片。每份注明希望参考什么。
- **生成环境**：实际平台和模型；不清楚时不要把建议参数当成已支持。

产品图应能说明本条要展示的角度。折叠、旋转、开合产品，补充运动前、中、后的结构及真实用法。不要只给正面图，却要求准确演示未知背部安装。

## 2. 选择工作方式

### 还没有想清楚

说“先帮我确定方向”。技能按需求、大纲、内容要求、产品外观逐步确认，已确认的信息不重复问。每一步给出你能直接纠正的复述。

### 已经有明确画面

说“直接写”。同时交代谁、在哪里、做什么、什么感觉。技能可以跳过重复确认，但不会把未知产品性能写成事实。

### 承接已有成片

给出上一段提示词与最后的实际画面状态，说明本段要发生什么。上一段文字描述和真实成片不一致时，以你确认的成片状态为准。若工具看不到视频，提供关键帧与文字说明，并保留未验证项。

## 3. 审核输出，再去生成

检查三个部分：

1. **分镜表**：卖点和动作是否可见、节奏是否装得下、起止状态是否接得上。
2. **提示词**：素材引用与实际上传顺序一致；产品款式、连接结构、物件去向和台词时序准确。
3. **任务参数**：确认当前平台支持建议的时长、画幅与分辨率。

只把最终提示词代码块复制到生成平台。模型、分辨率等参数在平台设置；参考图标签按该平台实际方式绑定，不能假设所有平台都识别同一套 `@图片` 语法。

原技能在提示词代码块之外保留作者署名行。那是交付文字，不属于模型输入，不要一起粘贴到生成平台。

安装本技能不会创建视频任务。账号、生成费用、素材上传和下载由所用平台或另行配置的工具负责。

## 4. 看完整成片，具体地反馈

不要只说“不够真实”。说清楚时间点、对象和变化，例如：

> 第 2 镜约 6 秒，右手松开瓶子后瓶子消失；预期它留在左格内。其他镜头和台词保留。

技能会区分可观察症状与原因假设，并提出局部修改。一次只改变一个主要变量，便于判断改写是否有效。要重跑几次取决于预算和授权，不需要为了遵循模板自动多跑。

检查重点包括：产品是否同款、动作接触是否合理、人体是否异常、道具是否守恒、口播是否对时、字幕是否符合要求、结尾是否仍有自然动态。结构检查通过不代表视频效果通过。

## 5. 如何更新

Git 安装且没有自定义改动时，在技能目录执行：

```bash
git status --short
git pull --ff-only
```

有修改时先备份或提交到你自己的分支，再处理更新；不要强制覆盖。ZIP 安装用户可先把旧目录改名备份，再放入新版，避免混合新旧参考文件。

## 6. 常见问题

**找不到技能？** 检查目录层级是否多套了一层，`SKILL.md` 应直接位于 `seedance-han/` 下；目录名、文件头的名称和调用名一致。参考文件要一起安装。重开会话后仍找不到，请查看客户端的技能发现规则。

**为什么总在问问题？** 方向不明确时使用逐关确认；可以说“按以下约束直接写”，补齐主体、场景、动作和风格，跳过不必要的确认。

**只有普通聊天工具能用吗？** 可以把入口和相关参考材料提供给能读取文件的助手作为工作指引，但不等同于已安装技能，也不能保证所有客户端支持自动路由。

**可以直接保证一比一还原吗？** 不能。参考图和文字用于约束，真实产品结构与关键印刷仍要验收。缺少的视角先补素材，或减少未知面展示。

**它是 API 工具吗？** 不是。仓库没有生成脚本和账户配置，也不包含作者机器上的历史归档。

**支持哪些模型？** 方法面向 Seedance 中文创作。具体平台能力会变，使用前核实；此仓库不维护跨供应商模型规格表。
