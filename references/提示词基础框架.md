# 提示词基础框架（林韩口述 · 2026-08-13）

> 等级 **✅生产验证**。**所有类型都以这个为基底，再做更精细化的补充。**
> 与《排版_成稿模板》的分工见文末第五节。

---

## 一、六段结构

```
1. 素材解释      @图片 + 描述补充，每个素材都要
2. 视频风格      2D动漫 / 3D动漫 / 平面动画 / 渲染特效 / 现实实拍
3. 摄像机设备    专业摄影 / 手机拍摄 —— 不需要非常具体
4. 视频内容      剧本主体，按时间线推进
5. 补充要求      一镜到底 / xx 保持和参考图一致不变
6. 负面提示词    一般只写：无背景音乐、无字幕
```

### 1 · 素材解释

上传了什么就 **@对应图片 + 描述补充**。**每个素材都要，一个不漏。**

### 2 · 视频风格

**图片素材对结果的权重高于文本**，所以风格声明必须与图片素材**保持一致**——不一致时结果偏向图片，写了也白写。

### 3 · 摄像机设备

**不需要非常具体。** 说清是专业摄影还是手机拍摄这一档就够。

### 4 · 视频内容（主体）

按时间线推进。**每个分镜开始，先说清各元素之间的关系，顺序固定：**

> ### 大环境 → 环境里元素之间的位置关系 → 交互关系
> （交互关系不一定每个东西都有）

**写法接近看图写话 / 写小说**——先把这一刻的画面交代清楚，再让它动起来。

### 5 · 补充要求

放在文本结尾。典型两类：镜头纪律（"保持一镜到底"）、一致性纪律（"xx 保持和参考图一致不变"）。

### 6 · 负面提示词

**一般只写「无背景音乐、无字幕」。** 不做别的负向堆叠。

## 二、核心语法：以镜头为主体出发

**画面内容的描述一律以镜头为参照系。**

| | |
|---|---|
| ❌ | "人物走向远处" |
| ✅ | "人物走向场景远处的树的方向" |

**机制（为什么必须写死）**：没指定走位方式，模型会**随机抽选**——可能转身背对镜头走过去，也可能看着镜头向后退步。两种都合法，所以模型自己挑。**有要求就必须显式写出来，没写就等于交给抽卡。**

**镜头本身也参与描述**，它是画面里的一个"物"：
> "镜头也缓缓后退，和人物保持固定距离。"

---

## 三、交互关系：台词的插入时序

**台词写在它发生的那个时间点上——文本顺序即时间顺序。**

| 想要的时序 | 台词写在哪 |
|---|---|
| 先说话，再做动作 | 写在**整体状态描述之后、动作之前** |
| 做完动作再说话 | 写在"他做完 xx 动作"那句的**后面** |
| 边做边说 | **并进动作句**（"边走边说…"） |

交互关系是这套框架里最复杂的一环——台词只是其中一类。凡是"谁对谁做了什么、什么时候做"的，都靠**文本位置**编码时序。

## 四、标准语感样本（口述原例）

> 环境是公园，远处是树，中间是空旷的草坪，近处是一小片矮花，站在草坪上，镜头对着人物，时不时有微风吹过，人物的裙子随风摆动，背景的树叶也随风轻微摆动。人物双手放在身后，然后伸出左手整理了一下自己的头发到耳后。面带微笑，小步向镜头逐渐走进，边走边说我今天好看吗。镜头也缓缓后退，和人物保持固定距离。

**逐段解剖：**

| 成分 | 原文 |
|---|---|
| 大环境 | 环境是公园 |
| 位置关系（由远及近） | 远处是树 → 中间是空旷的草坪 → 近处是一小片矮花 → 站在草坪上 |
| 镜头关系 | 镜头对着人物 |
| 环境动态（一个起因、两处受力） | 微风吹过 → 裙子随风摆动 + 树叶随风轻微摆动 |
| 人物动作 | 双手放在身后 → 伸出左手整理头发到耳后 |
| 表情 | 面带微笑 |
| 移动 + 台词并进 | 小步向镜头逐渐走近，边走边说"我今天好看吗" |
| 镜头响应 | 缓缓后退，和人物保持固定距离 |

**这段的密度就是"没有特殊要求"时的基准档。**

要提高某个元素的精度，就把**那一个元素**升到细描或参考图（见《资产决策》第四节的三档表）——"什么树、多高的树、叶子的状态、风从哪里吹向哪里"。**不是整段一起加密。**

## 五、与《排版_成稿模板》的分工（2026-08-13 已裁决）

> **本框架是默认模板。区块头模板不是另一套排版，而是一组"约束画面的延伸方式"——按需修改与补充进本框架，不整套替换。**

**触发条件**（命中才加装，见 `SKILL.md §2.2` 的完整表）：

| 延伸件 | 触发 |
|---|---|
| 色卡 `[色彩]` ＋ 完整风格锁 `[STYLE LOCK]` | **30s 及以上长片** ／ **片中出现多个场景** |
| 声场分层 `[声音]` | 多分镜硬切要缝合 ／ 音源复杂 |
| 取用范围限定 | 上了参考图（必装） |
| 「切镜头」＋ 分镜尾声音行 | 多分镜 |
| 承接几何重建 | 系列续写 |

**三处不一致的裁决结果：**

1. **区块顺序** —— 六段为准；区块头成分按上表插进对应段落，不另起一套骨架。
2. **负向纪律** —— **以本框架为准**：默认只写「无背景音乐、无字幕」。理由（林韩原话的机制）：器材稳定性、人物着装、动作形态这些**已经在正文或参考图里正向表达清楚了**，再补一句"禁止 xx"，反而会因为文本里出现了这个词让模型误判并生成它。落笔前先问"这件事能正向写清楚吗"，能就正向写。旧的"六类法定点位"降级为**排除式澄清的候选点位**（现存清单以 SKILL.md 铁律 7 为准），只在模型有强默认倾向、正向声明后仍会漂时才用（🔬 待验证；器材稳定性点位已于 2026-08-13 整条删除，范例 K 里那句排除也已同步清除——手持质感一律正向写）。
3. **器材详略** —— **不冲突**。本框架说的"不需要非常具体"指的是**器材档位**（专业摄影／手机拍摄）；`[STYLE LOCK]` 里的生产真实性断言簇、材质颗粒清单、调色取向不属于"摄像头描述"，是**质感锁**，触发时照常写。

**精细化程度不预判**：需求持续变化，而且没看过成稿之前判断不出来够不够。做法是**按基础档出一版 → 交付里列「可加精项」→ 由林韩挑**。
